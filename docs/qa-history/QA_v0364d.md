# v0.36.4d — Anatomical hitbox foundation

## Scope
- Added `src/anatomy_hitboxes.js`, an original, dependency-free, read-only anatomical contact geometry module.
- 15 capsule regions per player: helmet, torso, pelvis, plus upper arm, forearm, hand, thigh, shin, and foot on each side.
- Height adjusts body geometry; weight adjusts breadth within bounded ranges. Neither determines tackle success.
- Samples current position/facing and procedural pose (run, stance, dive, ground/recovery).
- Calculates capsule-to-capsule contacts and sampled swept path contacts.
- Exposes `game.debugAnatomy(key)` and `game.debugAnatomyPair(key1,key2)` through the existing in-browser debug API.
- No changes to live tackles, existing blocks, scoring, ball flight, AI, or animation outcomes.

## QA
- PASS: seven deterministic geometry checks in `qa_v36_4d_anatomy.js` covering stature, breadth, segment list, turning, falling, contact/no-contact and fast crossing.
- PASS: `node --check` for engine and anatomy module.
- PASS: standalone build equivalence via `python build_standalone.py --check`.

## Limitations / next step
- Early geometry is an approximation of the procedural player model, not an exact mesh. Currently read-only.
- Animated limb rotations are approximated; future rig joints should be shared explicitly with collision to remove divergence.
- Swept testing is discrete subdivision, not mathematically exact continuous time-of-impact.
- Requires a dedicated playable collision test scene with contact overlays and controlled tackle scenarios before connecting geometry to live tackling.
- This does not fix the previously observed dive-through-legs bug yet.

## Future-architecture note
- Player personality, mental event triggers, remembered teammate embarrassment, and nemesis rivalry will influence decision selection, not falsify physical collisions or add arbitrary physics bonuses.
