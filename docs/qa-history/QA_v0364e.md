# CHAOS / Gridiron Lab v0.36.4e — Contact evidence & reproducible test lab

## Scope and status
1. **Live anatomical contacts (observational):** all live ball-carrier/defender proximity pairs, including a committed diving defender, are sampled for 15 body-region capsules. Contact entries record the anatomical regions involved and relative speed. Optional full-scan mode covers offense/defense pairs. This does not change tackle probability.
2. **Between-frame checks:** sampled swept capsules across previous/current player transforms (adaptive temporal subdivisions). Finds crossings missed by end-of-frame overlap tests. This is NOT an exact mathematical continuous collision solver; very high speed or complex pose transitions may require refinement.
3. **Repeatable test mode:** a new `CONTACT LAB` game control scrolls to an embedded isolated canvas. Presets: dive into legs, shoulder contact, wide miss, smaller DB vs larger runner, glancing contact. Pause/play, step one 1/60-second frame, drag timeline, size presets, export JSON.
4. **Diagnostics:** field-side lab shows top-down/side-view capsule geometry and highlights intersecting regions; LIVE CONTACT LOG button displays records from actual gameplay, including evidence of any existing radius-based tackle that did not overlap an anatomical capsule. `GRIDIRON_DEBUG.debugContactEvidence`, `debugContactWatch`, and `debugContactReset` available for QA.

## Deliberate limitations
- **No change to tackle or hit-stick outcomes in v0.36.4e.** Legacy collision solver still decides those; a hitbox overlap alone is not an automatic tackle. This is necessary before calibrating contact geometry to physical contact.
- The model is anatomical capsule approximation, not exact mesh-triangle collision or a joint rig.
- Swept detection uses multiple samples along each frame and is not exact time-of-impact. Calibration and high-speed stress tests remain future work.
- Lab actors move along deterministic paths independent of the main match; their detected contacts do not simulate actual tackle outcomes.
- Live entry events are bounded (most recent 160) to avoid growing memory usage; full-scan mode is intentionally opt-in for performance.
- Release compliance: no new external assets or libraries. Historical licensing is NOT audited or certified.
