# Gridiron Lab v0.36.3a — Defensive air-control and dive transition hotfix

## Behavior changes
1. **Airborne defensive actions need proximity.** A defender within **5 yards of the projected catch point** or **3.7 yards of the current airborne ball** can use X swat, A play receiver, and Y ball-hawk. These radii only allow choosing an action; actual catches/deflections still use existing physics, reach, jump, timing, player ratings, and contact checks.
2. **Defenders far from the football** cannot initiate A/Y air actions or falsely animate a remote catch. X remains the normal committed tackle dive (aimed by left stick or current facing); there is no magnetic reach to the ball. B switching is unchanged.
3. **Diving motion is one commitment.** AI and manual steering cannot restart the athlete's running movement in the middle of a dive. A missed dive ends directly into a grounded/resting state before the existing rise animation, eliminating a redundant second fall. Arms reach forward during dives rather than trailing backward.
4. **Contextual HUD.** Air-action buttons appear only when the selected defender is within the contest zone. The status line distinguishes in-range ball actions from an out-of-range X dive.
5. **Scope.** No change to tackle outcome probability, diving cooldown, Y interception probability, offensive receiver selection, contact/blocking physics, Mesh, halftime, or defensive formations.

## Limitations / not claimed
- The legacy `qa_v28_xbox_ball_air.py` assumes a swat from *any* defender regardless of position, so its old remote-action expectation is no longer the intended behavior. New controller tests cover near and far cases.
- `qa_v16_formation_matrix.py` timed out in this run and is **not marked passing in this patch**, despite having passed in v0.36.3. We did not change formation code.
- The user's precise observed double-move sequence was not recorded, so the revised transition is verified structurally and through the dive lifecycle tests but still needs visual gameplay confirmation.
